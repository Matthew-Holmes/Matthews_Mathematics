# Matthews_Mathematics
Repository of worksheets I've made

## Building

Pushing to `main` runs [`build-latex.yml`](.github/workflows/build-latex.yml), which compiles every
`.tex` file under `latex/` whose PDF is not already in S3, then uploads the results. Each PDF is named
after the last 12 characters of the commit that last changed its source, so editing a worksheet
produces a new filename and triggers a rebuild.

## Non-English documents

pdfLaTeX cannot typeset scripts outside its 8-bit font encodings, so Chinese, Japanese, Korean,
Arabic, Hebrew, Thai, the Indic scripts and similar need a Unicode engine instead. Before compiling,
[`005_classifyCompileEngine.sh`](.github/workflows/scripts/005_classifyCompileEngine.sh) inspects each
source file and routes it to the right one:

| Engine | Chosen when |
| --- | --- |
| **pdfLaTeX** | Default. Plain ASCII, accented Latin, `£`, `×`, `°` and the like. |
| **XeLaTeX** | The source contains characters from a script pdfLaTeX cannot render, or loads a Unicode-engine package (`ctex`, `xeCJK`, `fontspec`, `polyglossia`, `unicode-math`, `bidi`, …). |
| **LuaLaTeX** | The source loads a LuaTeX-only package such as `luatexja`. |

**This is automatic.** The script will detect Chinese characters that will need rendering automatically. Characters inside LaTeX comments are ignored, and will use the default compiler.

If a build routes a file unexpectedly, the `latex-compile-engines` artifact on the workflow run lists
the engine chosen for every file together with the reason.

### Writing a Chinese worksheet

The CI image has no system fonts, so a font name such as `SimSun` will not resolve. Use the fonts
that ship with TeX Live instead — `fontset=fandol` for Chinese:

```latex
\documentclass{article}
\usepackage[a4paper,margin=1in]{geometry}
\usepackage[UTF8, fontset=fandol]{ctex}

\begin{document}
一个矩形的长是 8 cm，宽是 5 cm。求它的面积。
\end{document}
```

Japanese and Korean work the same way with the fonts TeX Live provides (Haranoaji and
Baekmuk/Nanum respectively). Save the file as UTF-8.

### The `% !TeX program` flag

A magic comment in the **first few lines** of a file overrides the detection entirely:

```latex
% !TeX program = xelatex
```

It takes precedence over everything else, and TeXstudio and VS Code LaTeX Workshop honour the same
directive, so the file builds identically locally and in CI. Accepted values are `pdflatex`,
`xelatex` and `lualatex`.

Use it in the following cases, otherwise leave it out:

- **Forcing a document back onto pdfLaTeX.** Greek and Cyrillic characters route to XeLaTeX by
  default, because a bare `θ` in body text is a hard error under this repo's usual `[T1]{fontenc}`
  preamble. If you would rather handle them with `babel` and the `LGR`/`T2A` encodings, add
  `% !TeX program = pdflatex`.
- **Requesting an engine nothing else triggers.** For example, the non-Latin text is generated by a
  macro or pulled in at build time rather than typed literally in the source, so there is nothing for
  the scan to find.
- **Preferring LuaLaTeX over XeLaTeX.** Unicode-engine packages default to XeLaTeX because it is the
  faster of the two; ask for `lualatex` explicitly if you need its font handling or Lua scripting.
